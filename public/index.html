BRIEFING

Quatre systèmes.
Une seule mission.

Rétablir le datacenter. Lis les incidents, consulte les manuels et répare les fichiers JSON. En solo, le premier joueur qui valide les quatre missions remporte la course. En collaboration, chaque équipe partage un datacenter : la première équipe à prouver les trois communications puis réussir le contrôle final de son créateur gagne.

  1. Rejoins la salle avant le départ donné par l’admin.
  2. Commence dans le terminal par un diagnostic léger (état du service). Il indique les couches en échec et débloque la configuration.
  3. Corrige le fichier JSON. Redémarre le service depuis le terminal, puis teste une communication avec le voisin indiqué dans network-map.json.
  4. En solo, le ping vers gateway débloque la mission suivante. En collaboration, tous les postes sont accessibles dès le départ : cliquez un serveur pour vous répartir le travail. Les groupes peuvent compter de 1 à 4 membres ; aucun plafond de nombre d’équipes n’est imposé par le jeu.

Terminal simulé : help, ls, cat fichier, nano fichier, gedit fichier, status, set chemin valeurJSON, systemctl, ping, check network, reset, clear. Aucun shell réel n’est exécuté.

Les erreurs ne donnent pas de pénalité. Le chronomètre continue pendant la lecture. Une pause admin suspend le temps pour tous. Les temps sont ceux du serveur, réseau compris. En équipe, les fichiers sont partagés ; si un coéquipier a modifié une version ancienne, rechargez la version partagée au lieu d’écraser son travail. Vous pouvez télécharger votre copie locale avant de recharger. Le classement des joueurs encore en course représente seulement leur progression.

La même session navigateur correspond à un joueur. Utilisez des appareils ou profils distincts. Les classements sont visibles aux personnes possédant le code de salle.
